# FileBe

Файлы, редактор кода и файловый мессенджер на Expo / React Native. Русский интерфейс, Material-inspired карточки, полупрозрачные glass-панели. Самостоятельный дизайн: не копия исходного кода или ресурсов CX File Explorer.

## Быстрый старт

```sh
npm install
npx expo install --check
npm run check
npx expo start
```

Основа — **Expo SDK 58.0.21**, React 19.3.0, React Native 0.88.1. Для зависимостей требуется Node.js **22.18+**. Это текущая зафиксированная базовая матрица; перед каждым release CI запускает `npx expo install --check` и Expo Doctor. Android/iOS — целевые платформы. Web не заявлен.

Локальная нативная сборка (нужны Android SDK / Xcode соответственно):

```sh
npm run android
npm run ios
```

После первого `npm install` обязательно добавьте `package-lock.json` в Git; дальше ставьте зависимости через `npm ci`. Lockfile фиксирует транзитивные версии и нужен CI. `npm run verify` запускает парсер, unit-тесты и Expo Doctor. Перед локальным native build нужны Android SDK / Xcode. EAS build требует собственного Expo/EAS проекта и настроенных signing credentials.

## Что реализовано

- Реальные файлы в documentDirectory/FileBe, не массив фиктивных файлов.
- Папки, текстовые файлы, шаблон проекта с README.md/index.js/package.json.
- Импорт через системный picker; экспорт/отправка через системное share-меню.
- Список/сетка, поиск в текущей папке, сортировка по имени/дате/размеру.
- Долгое нажатие или ⋮ — множественное выделение.
- Копирование/вырезание/вставка, переименование без замены существующего файла.
- Корзина вне рабочей папки; восстановление последнего элемента. Без автоматического удаления.
- Две панели: **слева файлы, справа содержимое**. Автоматически на ширине от 760, принудительно кнопкой панелей на телефоне. На узком телефоне удобнее повернуть экран. На широком экране режим постоянно двухпанельный.
- Текстовый редактор UTF-8: номера логических строк, поиск, замена всех совпадений, undo/redo, TAB/скобки/символы/console.log, атомарное сохранение с проверкой версии файла и локальный автосохраняемый черновик с восстановлением при повторном открытии.
- Просмотр изображений; остальные бинарные файлы открываются/экспортируются системным меню.
- Быстрые кнопки: HTTP(S)-ссылка, известная URL-схема приложения, текущая папка. Долгое нажатие удаляет кнопку с подтверждением.
- «Избранное»: локальные сообщения и копии вложений сохраняются на устройстве.
- Опциональный **демо-общий чат Supabase**: email/password, текст и вложения до 8 МБ. Функция выключена по умолчанию (`EXPO_PUBLIC_ENABLE_CLOUD=false`) и выключена во всех EAS-профилях. Не используйте глобальную комнату в production.

## Облачный мессенджер

- Создать `.env` из `.env.example`, оставить `EXPO_PUBLIC_ENABLE_CLOUD=false` для production-кандидата. Включать `true` только для отдельного тестового Supabase-проекта; в клиенте допустим только anon/public key.
- SQL-схема является demo-only и открывает один общий канал всем пользователям этого проекта. Не включайте её для реальных пользователей до реализации изолированных комнат и Storage RLS по членству.

В EAS-профилях облако выключено. Даже `anon/public` key попадает в клиентский bundle и **не является секретом**; `service_role`/secret key нельзя помещать в приложение. Auth-токен хранится через SecureStore. SQL-схема ниже — только demo: **все пользователи одного Supabase-проекта видят весь общий канал и вложения**. Она не предназначена для конфиденциальных переписок и публичного запуска. Перед включением облака нужны отдельные комнаты, членство и RLS на сообщениях и Storage, квоты, антиспам, модерация, retention и production-тесты. E2EE, личные диалоги, пагинация, фоновые уведомления и офлайн-очередь не реализованы.

## Ограничения — прочитайте до сборки

- Это функциональная исходная v1, а не полный аналог CX. Managed Expo не даёт произвольный доступ к `/Android/data`, всем дискам, установленным APK и системным каталогам. Работа идёт в sandbox с импортом/экспортом. Для полного Android-проводника нужны SAF/native modules, отдельная работа с разрешениями и проверка политики Google Play.
- Нет SMB/FTP/WebDAV, ZIP-архиватора, root-доступа, LAN discovery, облачных дисков и терминала. Создание проекта создаёт файлы, но **не выполняет npm, JS, Python или команды**.
- Редактор — TextInput, не Monaco/LSP: без syntax highlighting, автодополнения, lint, горизонтального скролла и форматтера. Текст переносится; номера соответствуют логическим строкам и могут визуально расходиться на длинных переносимых строках. Ограничение открытия — 1 МБ; undo ограничен 80 состояниями. Не используйте как редактор многомегабайтных файлов.
- Glass — прозрачность/BlurView и скругления. Не системный Apple Liquid Glass. Размытие зависит от платформы; Android может показать полупрозрачный фон без системного blur.
- Быстрая кнопка приложения запускает известную URL-схему, а не автоматически найденный пакет. Целевое приложение должно быть установлено и поддерживать схему.
- Пакетные операции по нескольким файлам не транзакционные: при ошибке часть элементов могла быть уже перенесена. Редактор автоматически сохраняет локальный черновик примерно через 0,7 с, но это не замена кнопке «Сохранить». Черновики и локальные сообщения находятся в sandbox устройства; не храните здесь секреты, и задайте политику retention перед production.
- Локальное хранилище сообщений не зашифровано. Удаление/выход из чата не очищает локальные копии вложений; нужна отдельная политика retention перед production.
- В облаке видны последние 100 сообщений; пагинация, фоновые уведомления и офлайн-очередь не реализованы.
- Бинарные вложения — недоверенные данные. Приложение их не исполняет; открывайте только доверенные файлы. MIME задаёт клиент, это не антивирус.
- SQL не запускается автоматически. На устройстве и в Supabase необходима отдельная проверка.

## Ручной smoke-test

1. Создать папку и проект, открыть index.js, изменить/сохранить/переоткрыть.
2. В редакторе проверить поиск/замену, TAB, undo/redo; попытаться уйти с несохранёнными правками.
3. Импортировать текст и изображение; проверить сетку, поиск и экспорт.
4. Скопировать и перенести несколько элементов в другую папку; конфликт имени должен отклоняться.
5. Переместить файл в корзину и восстановить. Нельзя вставить папку внутрь неё самой.
6. Проверить split на телефоне в landscape и на планшете.
7. Создать кнопки ссылки, приложения и папки; проверить долгое нажатие.
8. Отправить в Избранное текст/файл, полностью перезапустить приложение, открыть вложение.
9. Настроить Supabase, с двух аккаунтов проверить общий чат/вложение; убедиться, что anon не читает таблицу/bucket и второй аккаунт не пишет от чужого sender.
10. Проверить работу без сети: локальный режим доступен, ошибка облака отображается пользователю.

## GitHub

Создайте пустой GitHub-репозиторий и добавьте файлы. При первом запуске выполните `npm install` и закоммитьте `package-lock.json`; затем используйте CI и `npm ci`.

```sh
git init
npm install
npm run verify
npm run release:check
git add .
git commit -m "Prepare FileBe release candidate"
git branch -M main
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

GitHub Actions проверит совместимость Expo, тесты, Expo Doctor и JS bundle export для Android/iOS. Это не заменяет EAS native build и тесты реальных устройств. Перед публикацией замените демонстрационный `com.filebe.app` на собственный уникальный iOS/Android application id, настройте EAS и подпись, добавьте privacy policy, поддержку аккаунтов, store metadata и production QA. Базовые команды:

```sh
npm install -g eas-cli
eas login
eas init
eas build --platform android --profile production
eas build --platform ios --profile production
```

iOS-сборка требует Apple Developer account и настроенных signing credentials. Эта исходная копия не содержит EAS project id или ключей подписи; store submission не автоматизирован. `.env`, `node_modules` и native build-каталоги исключаются; в репозитории не должно быть `service_role` ключа.
